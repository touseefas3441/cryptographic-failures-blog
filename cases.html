03 / Real World

Real-World Cases

These cases show how mistakes in cryptographic software or key generation can affect real systems.

01
CASE 01 / 2014

Heartbleed

Heartbleed was a vulnerability in the OpenSSL cryptographic library.

It allowed attackers to read parts of a vulnerable system's memory. This could expose passwords, private keys and other sensitive information.

OpenSSL CVE-2014-0160 TLS Memory Leak
Lesson: Even when strong encryption is being used, a vulnerability in its implementation can expose the information it is supposed to protect.
02
CASE 02 / 2008

Debian OpenSSL Bug

A change made to Debian's OpenSSL package accidentally removed important sources of randomness.

This made many cryptographic keys predictable. The problem affected keys used for services such as SSH and SSL.

OpenSSL CVE-2008-0166 Weak Randomness Predictable Keys
Lesson: Cryptography depends not only on the algorithm, but also on secure key generation and randomness.
