Why Current Evidence Matters

Cryptographic security is not a fixed topic. Algorithms, protocols, libraries, attack techniques and security standards change over time.

For this reason, developers need to use current security guidance instead of relying only on older recommendations.

Evidence used in this section:

The main sources used are the OWASP Top 10:2025 and guidance from the National Institute of Standards and Technology (NIST).

1. OWASP Top 10:2025

The current OWASP Top 10:2025 identifies Cryptographic Failures as category A04:2025.

OWASP describes this category as covering failures related to missing cryptography, insufficiently strong cryptography, cryptographic key exposure and related errors.

Current OWASP evidence:

The 2025 OWASP data maps 32 Common Weakness Enumerations (CWEs) to Cryptographic Failures.

The dataset reported by OWASP contains more than 1.6 million total occurrences across the mapped CWEs and 2,185 CVEs.

These figures describe the dataset used by OWASP for the 2025 category. They should not be interpreted as meaning that 1.6 million individual web applications experienced a cryptographic failure.

2. Common Technical Problems

The current OWASP category includes several different types of cryptographic weaknesses.

Problem Example
Weak algorithms Using obsolete or risky cryptographic algorithms.
Weak randomness Using predictable random values when cryptographic randomness is required.
Key management errors Keys are poorly stored, reused, exposed or not properly managed.
Unprotected transmission Sensitive information is transmitted without adequate transport protection.
Weak password storage Passwords are stored using unsuitable hashing or encryption methods.
Hard-coded secrets Cryptographic keys or other secrets are placed directly in source code.

3. NIST and Cryptographic Key Management

NIST describes cryptographic key management as the handling of keys and related security information throughout their lifecycle.

This includes activities such as:

  • Key generation
  • Key storage
  • Key distribution or establishment
  • Key use
  • Key protection
  • Key destruction
Why this matters:

A strong cryptographic algorithm cannot protect information properly if its keys are exposed or badly managed.

4. A Changing Security Environment

Current cryptographic guidance increasingly considers the need to prepare systems for future cryptographic changes.

OWASP's 2025 guidance specifically recommends that organizations prepare for post-quantum cryptography and consider the migration requirements of systems with long security lifetimes.

This demonstrates an important principle: cryptographic security requires long-term planning rather than simply selecting an algorithm once and never reviewing it again.

5. Comparison of Current Guidance

Source Main Focus Key Message
OWASP Top 10:2025 Web application security Avoid weak or missing cryptographic protection and manage keys, randomness, passwords and protocols securely.
NIST Cryptographic key management Keys need protection throughout their complete lifecycle.
Real-world incidents Practical consequences Incorrect implementation or configuration can turn cryptographic mechanisms into security weaknesses.

6. What the Evidence Suggests

The available guidance and documented cases show that cryptographic failures are not limited to choosing a weak encryption algorithm.

They can occur because of poor randomness, inappropriate algorithms, exposed keys, weak password storage, incorrect configuration or missing protection for sensitive data.

Reasoned observation:

Effective cryptographic security therefore depends on the complete system around the cryptographic algorithm, including implementation, configuration, key management and maintenance.

Important Limitations of the Evidence

Security datasets do not measure every security problem in the world.

Different organizations collect data using different methods, and vulnerability datasets can contain duplicate or differently classified records.

Therefore, statistics should be interpreted according to the population and methodology used by the source rather than being treated as a complete measurement of all cryptographic failures.
